# DataEdu

Учебная веб-платформа по базам данных, созданная специально для студентов педагогических направлений. Внутри собрано всё необходимое для обучения: интерактивные курсы с теорией и тестами, встроенный SQL-тренажер прямо в браузере и практические задания с автоматической проверкой. Для преподавателей предусмотрены подробная аналитика, электронная ведомость, встроенный чат со студентами и генерация сертификатов.

Подробное устройство системы и обоснование архитектурных решений описаны — в [ARCHITECTURE.md](ARCHITECTURE.md).
История разработки и хронология изменений зафиксированы в [ЧТО_СДЕЛАНО.md](ЧТО_СДЕЛАНО.md).

## Быстрый запуск на любой машине

Для запуска проекта потребуется только установленный **Python 3.13**. Отдельно разворачивать и настраивать сервер базы данных не нужно: в режиме разработки платформа из коробки работает на файловой СУБД SQLite.

```bash
python -m venv .venv
.venv/Scripts/activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env              # Windows (PowerShell): Copy-Item .env.example .env
python manage.py migrate
python manage.py load_dump        # курсы, теория, тесты и демо-данные
python manage.py set_demo_passwords
python manage.py setup_teacher_admin
python manage.py assign_question_topics
python manage.py tidy_demo_data
python manage.py seed_practice    # задания с автопроверкой
python manage.py seed_course_content  # задания к блокам курса и темы билетов
python manage.py create_study_group "ИСТ-21" --teacher petrova --course databases-for-teachers

python manage.py runserver
```

Откройте http://127.0.0.1:8000.

Обязательно активируйте виртуальное окружение. Без вызова activate система подхватит глобальный интерпретатор Python (или среду Anaconda с предустановленной версией Django 4.2). В этом случае запуск упадет с ошибкой AttributeError: module 'django.db.models' has no attribute 'CompositePrimaryKey', так как поддержка составных ключей появилась только в Django 5.2.
Убедитесь, что в начале командной строки появился префикс (.venv). Проверить версию фреймворка можно командой:
bash
python -c "import django; print(django.get_version())"
Используйте код с осторожностью.
Вывод должен быть формата 5.2.x. Как вариант, можно запускать проект без активации, обращаясь к интерпретатору напрямую: .venv/Scripts/python.exe manage.py runserver.

**Демо-вход:** преподаватель `petrova`, студент `dmitry`, администратор `admin`.
Пароль всех демо-аккаунтов — `dataedu2026`.

## PostgreSQL

Основная СУБД платформы — PostgreSQL. База SQLite используется только для быстрого локального запуска без установки сервера. Переключение между базами настраивается через переменные окружения в файле .env:

```
DB_ENGINE=postgres
DB_NAME=dataedu_django
DB_USER=postgres
DB_PASSWORD=...
DB_HOST=127.0.0.1
DB_PORT=5432
```

Дальше — `migrate` и `load_dump`.

## Развёртывание в Docker

Архитектура развертывания включает три контейнера: веб-приложение под управлением gunicorn, обратный прокси-сервер nginx перед ним и базу данных PostgreSQL.

```bash
cp .env.docker.example .env.docker
# заполнить SECRET_KEY, DB_PASSWORD, ALLOWED_HOSTS
docker compose --env-file .env.docker up -d --build
```

Первичная инициализация базы выполняется однократно сразу после успешного запуска всех контейнеров:

```bash
docker compose --env-file .env.docker exec web python manage.py load_dump
docker compose --env-file .env.docker exec web python manage.py setup_teacher_admin
docker compose --env-file .env.docker exec web python manage.py createsuperuser
```

Сайт работает на 80-м порту. Наружу открыт только он: само приложение и база данных доступны исключительно внутри изолированной сети compose.

Три частые ошибки при развертывании, которых стоит избегать:

• Флаг --env-file обязателен. Без него Docker Compose по умолчанию подтянет переменные ${...} из обычного .env, который настроен под локальную разработку на SQLite. В итоге база в контейнере поднимется с одними параметрами, а приложение будет пытаться подключиться к ней по другим.

• Установите SECURE_SSL=0, пока не выпущен сертификат. По умолчанию продакшен-конфигурация принудительно переводит весь трафик на HTTPS, что на обычном 80-м порту вызовет цикл бесконечной переадресации. После подключения SSL-сертификата верните значение 1 и не забудьте прописать ваш домен в CSRF_TRUSTED_ORIGINS.

• Пароль от базы фиксируется при первом запуске контейнера db и навсегда сохраняется в томе pgdata. Изменить его в дальнейшем можно будет только вручную через запросы внутри самой СУБД.
Раздачей статических файлов занимается nginx, а не Django: в директории static/vendor лежит движок PGlite весом 18 МБ, и его скачивание каждым пользователем намертво блокировало бы целый рабочий процесс gunicorn. Вся статика собирается на этапе билда образа и автоматически копируется в общий том при старте контейнеров.
Присылайте следующий фрагмент README (например, инструкцию по обновлению сервиса, резервному копированию или настройке SSL), перепишу в таком же аккуратном стиле и с сохранением всей разметки.


Обновление после изменений в коде:

```bash
docker compose --env-file .env.docker up -d --build
```

Миграции применяются при старте контейнера (`RUN_MIGRATIONS=0` отключает).

## Эксплуатация

```bash
DJANGO_ENV=prod \
SECRET_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(64))')" \
ALLOWED_HOSTS=dataedu.example.ru \
DB_HOST=... DB_NAME=... DB_USER=... DB_PASSWORD=... \
python manage.py collectstatic --noinput

gunicorn config.wsgi:application --workers 4
```

Профиль `prod` не запустится без заданного `SECRET_KEY`, с отладочным ключом или без параметров подключения к PostgreSQL. Эта защита встроена намеренно, чтобы исключить тихий старт продакшена на небезопасных настройках по умолчанию. Общий кэш и хранение сессий между несколькими рабочими процессами gunicorn активируются через переменную `REDIS_URL` (зависимость `redis` уже указана в `requirements.txt`).

Все настройки профилей — в `config/settings/`, в
[ARCHITECTURE.md §8](ARCHITECTURE.md).

## Проверка

```bash
python manage.py check           # системные проверки
python manage.py test            # 479 тестов
ruff check .                     # разбор кода
ruff format --check .            # форматирование
```

По умолчанию тесты выполняются на базе SQLite в оперативной памяти. Чтобы прогнать их на боевом движке PostgreSQL, используйте следующую команду:

```bash
DB_ENGINE=postgres python manage.py test
```

## Админ-панель

Интерфейс панели администратора построен на базе темы [django-jazzmin](https://github.com/farridav/django-jazzmin), которая добавляет удобное боковое меню, быстрый поиск по разделам и тёмную тему. Все параметры оформления вынесены в файл
`config/settings/admin_ui.py`; при этом ни один стандартный класс `ModelAdmin` не пришлось переписывать вручную.

Загрузка внешних шрифтов с CDN в настройках Jazzmin принудительно отключена (use_google_fonts_cdn: False) — подробнее о причинах можно прочитать в разделе ниже. Соблюдение этого правила контролирует автоматический тест: `core.tests.test_accessibility.AutonomyTests`.

Задания с автопроверкой. Внизу страницы редактирования любого SQL-задания расположена кнопка «Посчитать эталон». Она запускает заготовку данных и эталонный запрос прямо в браузере — в том же движке PostgreSQL, который используют студенты, — и сразу сохраняет результат. Расчёт идёт по текущим значениям в полях формы, поэтому предварительно сохранять само задание не требуется. Расположенная рядом кнопка «Посчитать на сервере» выполняет аналогичную проверку на стороне СУБД и доступна только в том случае, если сам проект запущен на PostgreSQL.

Билеты итогового проекта. Все доступные формулировки хранятся в разделе «Темы проектов», где также отображается счётчик выпадений каждого варианта. Если снять тему с набора, она перестанет выпадать новым студентам, но сохранится у тех, кто уже успел её вытянуть. Номер учебного блока, после прохождения которого открывается доступ к билету, настраивается в параметрах самого итогового задания. При необходимости заменить тему конкретному студенту можно в разделе «Билеты итогового проекта» (быстрая ссылка на него есть прямо в карточке студента), при этом указанная причина замены будет видна учащемуся.

## Тренажёр

Полноценная песочница PostgreSQL прямо в браузере на базе PGlite расположена по адресу `/trainer/`. Студенту доступны четыре готовые схемы на выбор: «Университет», «Магазин», «Библиотека» и «Своя база» (чистое пространство для проектирования собственного проекта), причём схема «Университет» полностью совпадает с базой из практических заданий. Все изменения хранятся локально в IndexedDB браузера и не пропадают при перезагрузке страницы, а кнопка «Сбросить базу» в любой момент возвращает выбранный набор к исходному состоянию.

Рабочая область вывода растянута на всю ширину экрана и разделена на три функциональные вкладки:

- **«Результат»** — привычная таблица с полученными строками, текстовый план и показатели замера времени.
- **«Как выполняется»** — наглядная пошаговая визуализация работы запроса на диаграмме. Показывает, какая именно часть SQL-кода сейчас отрабатывает, какие таблицы и столбцы затронуты, сколько строк было на входе, сколько осталось на выходе и какие записи прошли фильтрацию. Шаги строятся на основе реального плана (EXPLAIN ANALYZE внутри транзакции с последующим откатом), что позволяет безопасно разбирать даже модифицирующие запросы UPDATE и DELETE без изменения данных в базе. Промежуточные выборки отображаются только при точном совпадении их количества с планом.
- **«Диаграмма»** — • интерактивная ER-схема, построенная по внешним ключам: поддерживает масштабирование, свободное перетаскивание блоков и подсветку всех связей выбранной таблицы по клику.

Помимо базового запуска кода, тренажёр включает набор инженерных инструментов:

- **«Показать план»** — строит дерево EXPLAIN ANALYZE с процентными долями времени выполнения каждого узла и подсветкой расхождений между оценкой планировщика и фактом.
- **«Замерить»** — запускает серию из пяти прогонов и сравнивает результат с предыдущим замером этого же запроса, чтобы студент мог наглядно оценить эффект от добавления индекса.
- **«Выгрузить SQL»** — собирает всю структуру таблиц, ограничения, индексы и текущие данные в единый дамп-скрипт, полностью совместимый с серверным PostgreSQL.
- **«Ссылка»** и экспорт в CSV — позволяют упаковать текст запроса прямо в URL для быстрой отправки или скачать результат выборки в табличном формате.


На страницах практических заданий прямо над редактором кода выводится справочник по таблицам заготовки: список столбцов с типами данных, первые строки для понимания формата и схема связей. Работы, требующие ручной проверки преподавателем, отправляются текстом или файлом `.sql`/`.txt` прямо со страницы задания и сразу попадают в общую очередь на проверку.

Обложки учебных курсов генерируются на основе векторных иконок, отрисованных специально для проекта (`courses/cover.py`). Если у курса нет индивидуальной иллюстрации, ему автоматически назначается стандартная иконка базы данных.

Любая синтаксическая или логическая ошибка PostgreSQL сопровождается понятным пояснением на русском языке. При этом на сервер передаётся исключительно обезличенный класс ошибки — он используется для формирования сводного отчёта «На чём спотыкаются» в аналитике преподавателя. Сам текст запроса и детали ошибки никуда не отправляются и не сохраняются.

## Автономность

Платформа работает полностью автономно и не отправляет ни одного внешнего сетевого запроса: все шрифты, обложки курсов и движок PGlite (PostgreSQL, скомпилированный в WebAssembly) хранятся локально в директории static/. Это строгое требование безопасности изолированного контура, в котором развёртывается система — и именно поэтому все SQL-задания студентов выполняются непосредственно в их браузере, а не на стороне сервера.
