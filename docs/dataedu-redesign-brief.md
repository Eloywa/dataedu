# Бриф: редизайн DataEdu

Я делаю образовательную платформу DataEdu для обучения основам PostgreSQL студентов педагогических направлений. Платформа бесплатная, будет использоваться в вузе, коммерции нет. Мне нужен редизайн всех страниц в одном стиле, с хорошей версией для телефона.

Этот файл описывает, как всё должно выглядеть и вести себя. Реальное содержимое (названия модулей, уроки, тесты, задания) бери из существующего проекта, ничего не выдумывай и не оставляй вымышленные названия из описаний ниже.

## 1. Общая идея

- Спокойный, серьёзный, современный интерфейс для университета.
- Две опоры: академичный стиль (тёплый светлый фон, один основной цвет, тонкие линии) и логика технической документации (боковая навигация, много места для текста и кода).
- Фирменный образ сайта: тонкие линейные ER-диаграммы таблиц и связей между ними.
- Это учебный ресурс, а не рекламный лендинг. Никакого маркетингового тона.

## 2. Визуальный стиль

### 2.1 Цвета (design tokens)

Вынеси цвета в CSS-переменные, чтобы их можно было поменять в одном месте (например, под фирменные цвета вуза).

```css
:root {
  --bg: #FAF9F6;            /* общий фон, тёплый off-white */
  --surface: #FFFFFF;       /* карточки, панели */
  --text: #1B1F24;          /* основной текст */
  --text-muted: #4B5563;    /* вторичный текст, достаточный контраст */
  --border: #D9D6CF;        /* тонкие линии */
  --primary: #1F3A5F;       /* единственный основной цвет */
  --primary-hover: #16304F;
  --note-bg: #EEF2F7;       /* блоки "Обратите внимание" */
  --code-bg: #F3F4F6;       /* фон кода */
  --success: #2E7D4F;       /* только для успеха */
  --success-bg: #E8F3EC;
  --error: #B3261E;
  --error-bg: #FBEAE9;
  --focus: #1F3A5F;
}
```

Основной цвет один. Зелёный и красный используются только для состояний (успех, ошибка).

### 2.2 Шрифты

- Основной шрифт для всего текста и заголовков: **Golos Text** (веса 400, 500, 600).
- Шрифт для кода: **JetBrains Mono** (или IBM Plex Mono), вес 400.
- Шрифты подключить **локально** (файлы woff2 лежат в проекте), не через внешние сервисы. Подмножества: кириллица и латиница. `font-display: swap`.
- Перед подключением проверь лицензию каждого шрифта на его официальной странице и положи файл лицензии рядом со шрифтами.
- Запасные шрифты в `font-family`: system-ui, Arial, sans-serif; для кода: ui-monospace, Consolas, monospace.
- Засечек в интерфейсе нет.

### 2.3 Типографика

- Основной текст уроков: 17-18 px, межстрочный интервал 1.6, ширина текстовой колонки не больше 68 символов.
- Остальной интерфейс: не меньше 16 px.
- Заголовки: вес 600, плотный межстрочный интервал (1.2-1.3), размеры по шкале (h1 32-40 px на десктопе, 28 px на телефоне).
- Код: 15-16 px.

### 2.4 Формы и отделка

- Скругление 6 px. Крупных скруглений нет.
- Границы 1 px цветом `--border`.
- Без теней, без градиентов, без 3D, без глянцевых иконок.
- Иконки только тонкие линейные, один набор.
- Много воздуха, строгая сетка, отступы кратны 8 px.

## 3. Страницы

### 3.1 Главная
- Шапка: слева заглушка под логотип вуза (контурный прямоугольник с пунктирной рамкой и подписью "Логотип вуза"), название DataEdu, ссылки "Курс", "Тренажёр", "О проекте". На телефоне ссылки уходят в меню-бургер.
- Первый экран: крупный заголовок "Основы баз данных на PostgreSQL", подзаголовок "Учебный курс для студентов педагогических направлений", кнопки "Начать с введения" (основная) и "Программа курса" (контурная).
- Справа от заголовка (на телефоне под кнопками) линейная ER-диаграмма. Нарисовать её как SVG с реальными учебными таблицами (например students, groups, grades), с понятными связями. Не использовать подписи вроде Table1.
- Блок "Цели курса" и блок "Что вы научитесь делать": короткие списки. Текст целей взять из диссертационных материалов проекта, если они там есть, иначе оставить заглушки и пометить.
- Список модулей: нумерованный, на телефоне свёрнутый в аккордеон.
- Подвал: заглушка с названием кафедры, место под логотип вуза.

### 3.2 Программа курса
- Один список модулей в виде раскрывающихся блоков (без дублирования с боковым меню).
- В каждой строке: номер, название, число уроков, статус текстом ("Не начат", "В процессе", "Пройден"). Статус не передаётся только цветом.
- Общая тонкая линия прогресса сверху.
- При раскрытии модуля видны его уроки со ссылками.

### 3.3 Урок
- Формат документации: слева дерево модулей и уроков (текущий выделен левой границей `--primary`), по центру текст урока, справа "Содержание урока" с якорными ссылками (на широких экранах).
- Элементы текста: абзацы, блок "Обратите внимание" (фон `--note-bg`, тонкая левая полоса `--primary`), блок кода, таблицы-примеры.
- Внизу кнопки "Назад" (контурная) и "Следующий урок" (основная).

### 3.4 SQL-тренажёр
- Верх: хлебные крошки "Модуль N / Задание N.M".
- Левая панель: условие задания, сворачиваемая "Подсказка", схема таблицы (имена столбцов и типы данных).
- Правая панель: редактор SQL с номерами строк, кнопки "Выполнить" (основная) и "Проверить" (контурная), ниже таблица результата и сообщение о результате проверки.
- Успех: спокойная зелёная строка с галочкой. Ошибка: понятное сообщение красным с пояснением простым языком.
- Логика (PGlite, автопроверка) остаётся как есть, меняется только внешний вид.

### 3.5 Тест после модуля
- Отдельная страница, только тест, без редактора кода.
- По центру узкая колонка: "Тест по модулю N", "Вопрос X из 5", тонкая линия прогресса, вопрос, варианты ответа как строки с радиокнопками, кнопки "Ответить" и "Назад".
- После ответа показать верно или нет и короткое пояснение.

### 3.6 Мой прогресс
- Три простых блока с цифрами (пройдено уроков, выполнено заданий, средний балл за тесты).
- Таблица модулей с тонкими линиями прогресса и процентами.
- Блок "Рекомендуем повторить" со ссылками на темы.
- Данные брать из существующей базы проекта.

## 4. Адаптивность

Одна и та же страница сама перестраивается под экран. Отдельных мобильных страниц не делать.

Точки перелома:
- до 640 px: телефон, одна колонка;
- 640-1023 px: планшет;
- от 1024 px: десктоп с боковыми панелями.

Что меняется:
- Боковое дерево модулей на экранах меньше 1024 px превращается в выезжающее меню (открывается кнопкой, закрывается по касанию вне него и по кнопке).
- Колонка "Содержание урока" на экранах меньше 1024 px прячется в раскрывающийся блок вверху урока.
- Кнопки "Назад" и "Следующий урок" на телефоне закреплены внизу экрана на всю ширину.
- Таблицы и блоки кода никогда не раздвигают страницу: у них своя горизонтальная прокрутка внутри блока.
- Размеры зон нажатия не меньше 44 на 44 px.
- Основной текст не меньше 16 px (иначе iPhone приближает страницу при нажатии на поле ввода).

## 5. SQL-редактор на телефоне (отдельное внимание)

Это самое сложное место сайта.

- Вместо двух колонок две вкладки: "Задание" и "Код". Результат показывается под редактором на вкладке "Код".
- Шрифт в редакторе не меньше 16 px.
- Над экранной клавиатурой строка быстрых символов: `'`, `"`, `=`, `;`, `>`, `<`, `*`, `(`, `)`, `AND`, `OR`, `NOT`, `NULL`. Строка прокручивается по горизонтали, каждая кнопка не меньше 44 px по высоте. Нажатие вставляет символ в позицию курсора.
- Кнопки "Выполнить" и "Проверить" на всю ширину, закреплены так, чтобы не уезжать под клавиатуру.
- Отключить автокоррекцию, автозаглавные буквы и подсказки браузера в редакторе (`autocorrect="off"`, `autocapitalize="off"`, `spellcheck="false"`).
- Таблица результата прокручивается по горизонтали внутри своего блока.
- Проверить, что PGlite работает на телефоне без заметных зависаний. Если страница тяжёлая, показывать индикатор загрузки и не блокировать интерфейс.

## 6. Компоненты

Сделай небольшой набор переиспользуемых компонентов в едином стиле:
- кнопки (основная, контурная, неактивная, состояние загрузки);
- ссылки в тексте;
- карточка и панель (белая поверхность, граница 1 px);
- блок "Обратите внимание", блок "Подсказка";
- блок кода и встроенный код;
- таблица данных (заголовок на `--code-bg`, тонкие линии);
- аккордеон;
- полоса прогресса;
- метка статуса с текстом;
- радиокнопки и варианты ответа в тесте;
- меню-бургер и выезжающее меню.

## 7. Доступность и контраст

- Контраст текста не ниже WCAG AA (4.5 к 1 для обычного текста).
- Видимая рамка фокуса у всех интерактивных элементов (контур 2 px цветом `--focus`, смещение 2 px).
- Полное управление с клавиатуры (меню, аккордеоны, тест, тренажёр).
- Смысловая разметка: один h1 на страницу, правильные уровни заголовков, `nav`, `main`, подписи к полям.
- Состояния не передаются только цветом, всегда есть текст или значок.
- Поддержка `prefers-reduced-motion`: анимаций почти нет, а те, что есть, отключаются.

## 8. Что оставляем заглушкой

- Логотип вуза: контурный блок с подписью "Логотип вуза". Настоящую символику ставим только после согласования.
- Название кафедры в подвале: текст-заглушка.
- Отзывы и статистика: не добавлять, пока нет реальных данных.
- Цвета вуза: если появятся, меняем только токены из раздела 2.1.

## 9. Чего в дизайне быть не должно

- 3D-объектов, глянцевых иконок, градиентов, теней.
- Промо-элементов: бейджей со скидками, акцентных баннеров, слов вроде "бесплатно" и "акция".
- Засечек и декоративных шрифтов.
- Больше одного основного цвета.
- Выдуманных цифр, названий и отзывов.
- Копирования чужого брендинга, логотипов и иллюстраций.

## 10. Порядок работы

1. Подключить шрифты и завести токены (цвета, размеры, отступы) в одном файле стилей.
2. Сделать базовые компоненты из раздела 6 и страницу-пример с ними.
3. Перевести страницы в таком порядке: урок, тренажёр, главная, программа курса, тест, прогресс.
4. После каждой страницы проверить её на ширине 390 px и на 1440 px и показать мне скриншоты.
5. В конце прогнать проверку контраста и работы с клавиатуры.

Если что-то в брифе противоречит существующему коду или данным проекта, не переделывай молча. Остановись и напиши мне, в чём конфликт.
