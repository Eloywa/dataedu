# DataEdu (Django) — журнал миграции

Перенос DataEdu с Next.js на Django (монолит + HTMX, тренажёр на PGlite).
Next-версия не трогается — это защищаемый артефакт 1-го года. Идём по этапам.

## Этап 1 — каркас Django ✅ (25.06.2026)

- Окружение: **uv**, Python 3.13, **Django 5.2.15**, psycopg 3.3, python-dotenv
  (зависимости — в `pyproject.toml` / `uv.lock`).

  шаблоны `templates/`, статика `static/`, язык `ru`, таймзона `Europe/Moscow`,
  секреты из `.env` (в git не входит; есть `.env.example`).

  главная отображается в дизайне Terminal.

### Заметки по окружению (Windows) — важно для следующих этапов
- В системе включён **SOCKS-прокси** (Internet Settings) → uv/pip падают с «tunnel
  error». Обход: ставить пакеты с `NO_PROXY='*'` (напр. `NO_PROXY='*' uv add ...`).
- Postgres: подключаться по **`127.0.0.1`** (IPv4); `::1` (IPv6) блокируется
  фаерволом (ошибка 10013). Учётные данные БД — те же, что у Next-версии (лежат в
  `.env`, в git не входят).
- Запуск сервера: `NO_PROXY='*' uv run python manage.py runserver`.

## Этап 9.5 — автономность: ноль внешних запросов ✅ (30.07.2026)

Задача ставилась как «вшить PGlite вместо CDN», но при разборе нашёлся второй,
более массовый внешний запрос — шрифты. Правило по итогу: **готовая страница не
делает ни одного запроса за пределы своего домена.**

- **PGlite 0.5.4 вшит** в `static/vendor/pglite/` (~17 МБ): `pglite.wasm` (9,7 МБ),
  `pglite.data` (6,1 МБ), `initdb.wasm` (386 КБ), `index.js` + 7 `chunk-*.js`.
  Отброшены source maps, CJS-сборка под Node и `contrib/*.tar.gz` (расширения
  Postgres не используются). Импорт в обоих островках — относительный:
  `import { PGlite } from "../vendor/pglite/index.js"`.
- **Шрифты локально** — `static/vendor/fonts/`: 22 файла `woff2` (~364 КБ) и
  `fonts.css` с правилами `@font-face`, снятыми вместе с `unicode-range`, поэтому
  браузер качает только нужный субсет. Оставлены `latin`, `latin-ext`, `cyrillic`,
  `cyrillic-ext`; `vietnamese` и `greek` отброшены. Убраны `preconnect` и ссылка на
  `fonts.googleapis.com` из `base.html`.
- **Правовой довесок:** обращение к шрифтовому сервису уходило с *каждой* страницы и
  передавало в США IP и User-Agent студента — то есть трансграничная передача ПДн
  (ст. 12 152-ФЗ) без оснований. Теперь этого запроса нет. Подробный разбор —
  `docs/ARCHITECTURE-FULL.md` §17.14 (в Next-репозитории).
- **Исправлена типографика:** у Space Grotesk нет кириллицы, и русские заголовки
  до этого набирались системным фолбэком. Добавлен **Manrope** как кириллический
  компаньон: стек `"Space Grotesk", "Manrope", sans-serif` даёт поглифовый фолбэк.
- **MIME-тип wasm** зарегистрирован явно в `config/settings.py`
  (`mimetypes.add_type("application/wasm", ".wasm")`): PGlite поднимает движок через
  `WebAssembly.instantiateStreaming`, а тот требует строгий `Content-Type`. На Windows
  тип берётся из реестра, где записи может не быть, — без этой строки тренажёр падает
  на чужой машине.
- **`static/vendor/README.md`** — состав, лицензии (Apache-2.0 для PGlite, SIL OFL 1.1
  для шрифтов), процедуры обновления и запрет на добавление внешних CDN.

**Проверено** прогоном через CDP с перехватом `Network.requestWillBeSent`: по обеим
страницам 25 запросов, единственный хост `127.0.0.1:8000`, внешних запросов нет,
ошибок в консоли нет. `/trainer/` вернул 3 строки с корректными агрегатами;
задание «Средний XP» на `/practice/` получило серверный вердикт «верно» (балл 10.00,
статус `graded`). `check` чист. Скриншоты: `tmp_shots/s95_trainer_offline.png`,
`s95_practice_offline.png`.

**Две ловушки на будущее:**
1. `initdb.wasm` сначала пропустили — ссылка на него лежит не в `index.js`, а в одном
   из чанков. Первый прогон упал с `Failed to execute 'compile' on 'WebAssembly'`,
   в логе сервера был `404` на этот файл. Список ассетов снимать со **всех**

2. Geist, Space Grotesk и Manrope — variable-шрифты: один `woff2` обслуживает все веса.

## Этап 9.6 — правовой контур под 152-ФЗ ✅ (30.07.2026)

Замысел: платформе не нужно знать, кто стоит за учётной записью. Обезличенные данные
под 152-ФЗ не подпадают (ст. 3 п. 9), поэтому цель — **не становиться оператором
персональных данных**, а не выполнять весь набор обязанностей оператора.

- **Вход по логину-псевдониму** вместо email (миграция `accounts/0002`):
  `username` — уникальный `USERNAME_FIELD`, `full_name` → `display_name` и стал
  необязательным, `email` стал необязательным. Форма регистрации спрашивает **только
  логин и пароль**; поля для настоящего ФИО в системе больше нет. Логины существующим

### Важная поправка к методу проверки этапов

Обнаружилось, что прежняя формулировка «прогон в транзакции с откатом» не
соответствовала действительности: `transaction.savepoint()` вне блока `atomic`
(то есть в обычном autocommit-режиме) — **no-op, возвращает `None`**, и
`savepoint_rollback(None)` тоже ничего не делает. Скрипты печатали «транзакция
откачена», а записи оставались в базе.

Из-за этого в БД осели артефакты прогонов этапа 9.6: аккаунты `test.pilot`,
`tst-01…tst-03`, `adm.made` с их записями `Consent`, а от этапа 10 — лишняя рефлексия
Анны и начисленные ей 5 XP. Всё убрано вручную, база вернулась к 19 демо-аккаунтам.
Проверено, что `purge_metrics` в прогоне не уничтожил настоящие данные: самое старое
событие в `activities` — 05.09.2025, а порог чистки (400 дней) — июнь 2025.

Правильный способ, теперь применяемый в обоих скриптах:

```python
class Rollback(Exception):
    pass


try:
    with transaction.atomic():
        ...  # проверки
        raise Rollback
except Rollback:
    pass
```

Оба прогона (9.6 и 10) перезапущены заново: **60 и 32 проверки, 0 провалов**, и снимок
базы до и после совпал по всем счётчикам (`users=19`, `consents=0`, `reflections=22`,
`activities=194`, XP Анны 200) — вот это и есть доказательство отката. Впредь сверять
снимок обязательно, прежде чем писать «проверено с откатом».

## Этап 10.5 — конструктор заданий и диагностика автопроверки ✅ (30.07.2026)

### Диагностические подсказки вместо «верно/неверно»

- `grading.diagnose(...)` раскладывает итог на **три независимые проверки**: столбцы
  (совпало ли число), число строк (ожидалось / получено), состав строк (на сколько не
  хватает и сколько лишних — сравнение мультимножеств). `passed` берётся из того же
  расчёта, поэтому вердикт и разбор не могут разойтись.
- **Подсказка о вероятной причине** выбирается по форме расхождения: дубликаты там, где
  эталон уникален → пропущен `DISTINCT` или группировка; лишние без нехватки → условие
  отбора слишком широкое; нехватка без лишних → слишком узкое; и то и другое → расхождение
  в вычисляемых значениях или условии соединения. Это формирующее оценивание — студент
  получает направление, а не приговор.
- **Диагностика не раскрывает эталон**: в ответ уходят только количества, ни одного
  эталонного значения и ни одного названия эталонного столбца. Закреплено отдельным
  тестом, который ищет секретное значение и названия столбцов в теле ответа.
- Тот же разбор пишется в `Submission.feedback` — преподаватель видит ту же картину,
  и на этапе 11 по этому полю можно строить выборку.
- В островке — список проверок с галочками и подсказка янтарём. Заодно разделены случаи
  «ответ неверный» и «проверка не состоялась» (например, у задания нет эталона): раньше
  оба показывались как «неверно», хотя второе — не ошибка студента.

### Исправлен настоящий баг оценивания

`normalize_rows` строила `sorted(...)` из кортежей, и это падало с
`TypeError: '<' not supported between instances of 'str' and 'NoneType'`, если у двух строк

## Этап 11.5 — ведомость по группе, печать и выгрузки ✅ (02.08.2026)

### Учебная группа
Записи на курс для ведомости мало: один курс могут слушать две группы, а ведомость

`итог = 0.5·тесты + 0.3·уроки + 0.2·задания`, тесты — по **лучшей попытке** каждого

## Этап 12 — архитектура под нагрузку, паритет с Next-версией и тесты ✅ (06.09.2026)

Этап начинался как «адаптив и отделка», но требования изменились: платформу
планируют внедрять в контур университета, а значит сначала нужна архитектура, от
которой можно отталкиваться, — и полный паритет с первой версией, а не выборочный.

### Архитектура: описана и переделана

Появился **`ARCHITECTURE.md`** — не пересказ кода, а основания решений: расчётный
профиль нагрузки (до 20 000 учётных записей, 300–600 одновременно, пик по
расписанию занятий), слои и направление зависимостей между приложениями, форма
запросов, кэш, профили настроек и **список порогов, на которых эта архитектура
перестанет работать**.

Главный вывод разбора: узкое место платформы — не процессор, а число обращений к
базе на страницу. Отчёты делали запрос на строку.

| | было | стало |
| --- | --- | --- |
| Панель риска, поток 400 человек | ~1 200 запросов | **6** |
| Трудность уроков, курс на 50 уроков | ~200 запросов | **5** |
| Инбокс, 3 000 сообщений | выборка всей переписки | **3** |
| Каталог, страница из 24 курсов | 2 запроса на карточку | **3** |

Приём везде один: вместо обращения внутри цикла — групповой запрос и словарь по
ключу. Последнее сообщение диалога ищет **оконная функция** (`ROW_NUMBER()` с
разбиением по паре «собеседник + курс»). Числа закреплены тестами через
`assertNumQueries`: иначе возврат запроса в цикл проходит незаметно — отчёт
остаётся правильным, просто перестаёт открываться.

Ещё по нагрузке: **11 составных индексов** на горячих сочетаниях (прогресс по
курсу, лента активности, лучшая попытка, очередь проверки, счётчик непрочитанных);
**постраничный вывод** каталога и очереди с сортировкой **в базе**, а не в Python
(сортировка списка после выборки делает постраничность обманом); кэш отчётов со
сбросом по времени; `CONN_MAX_AGE` и `statement_timeout`.

### Профили настроек и переносимость

`config/settings.py` разделён на пакет: `base` / `dev` / `prod` / `test`, выбор — по
`DJANGO_ENV`, точка решения одна. Разработка идёт **на SQLite по умолчанию**:
`clone → migrate → runserver` работает на любой машине без установки СУБД.
Целевой СУБД остаётся PostgreSQL — профиль `prod` без неё не стартует, а не
переключается на файловую базу молча. Он же отказывается запускаться без
`SECRET_KEY` и с отладочным ключом: `.env` часто копируют из примера вместе со
значением по умолчанию, и в эксплуатацию уезжает ключ из открытого репозитория.

Наполнение — команда **`load_dump`**: разбирает `COPY`-блоки дампа Next-версии и
заливает 1 599 строк (8 курсов с теорией, 27 тестов, 116 вопросов, демо-данные об
обучении). Повторный запуск ничего не задваивает. Пароли не переносятся — в дампе
хеши scrypt, которые Django не понимает.

### Паритет: перенесено то, что раньше решили не переносить

На этапе 2 чат значился как «сознательно не переносим», на «доп.» — «без
сертификатов». Требование изменилось: переносим всё.

- **Переписка** (приложение `messaging`): диалог — пара «собеседник + курс», потому
  что один преподаватель может вести у студента два предмета. Живость сделана
  **опросом, а не SSE**: синхронный Django держит на каждое SSE-соединение отдельный
  поток и отдельное подключение к базе, и три сотни студентов с открытой вкладкой
  исчерпывают пул раньше, чем начнётся занятие. Виджет вопроса на странице курса,
  инбокс, живой бейдж непрочитанных. Переписка студент↔студент закрыта.
- **Сертификат**: открывается при 100% пройденных уроков, дата — по последнему
  закрытому уроку (а не «сегодня»), проверочный код — усечённый HMAC от пары
  «участник + курс» на `SECRET_KEY`: не хранится, по нему не восстановить
  идентификаторы, не подобрать без ключа. Печать браузерная, как у ведомости.
- **Проверка работ** (`/teacher/submissions/`): очередь с непроверенным сверху,
  балл, отзыв, «на доработку». Разбор формы вынесен в чистую функцию — балл
  приходит от недоверенной стороны.
- **Карточка студента** (`/teacher/students/<id>/`): курсы, уроки, тесты, рефлексия,
  достижения, зачёт защиты итогового проекта.

Изоляция авторства распространена на новое: работа берётся из `visible_submissions`,
а не «найти и потом проверить владельца» — во втором случае забыть проверку можно,
в первом проверять нечего.

### Тесты: было ноль, стало 331

Автотестов в Django-версии не было вообще (`tests.py` — заготовки из `startapp`).
Появился прогон в отдельном профиле (SQLite в памяти, кэш выключен, быстрое
хеширование) и фабрики вместо фикстур в JSON.

Покрыто три уровня: чистые формулы (риск, трудность, итоговая отметка, уровни,
gating, сравнение SQL, разбор формы проверки), выборки на данных (изоляция
авторства, агрегаты, число запросов) и страницы тест-клиентом (права, IDOR, формы,
выгрузки). Отдельно проверено, что диагностика автопроверки **не раскрывает эталон**,
что анонимный комментарий не показывается на карточке автора, и что `next` в форме
отправки не уводит на чужой хост.

### Четыре ошибки, найденные тестами

1. **Кириллический логин проходил регистрацию.** В форме стояла проверка
   `ch.isalnum()`, а она в Python истинна и для кириллицы, — при том что поле
   объявлено латинским валидатором. Логин служит ключом сопоставления при выгрузке
   в Moodle, и кириллица в нём ломает импорт. Проверка теперь одна на модель и форму.
2. **Поиск по русскому названию не работал на SQLite.** Встроенный `LIKE` приводит
   регистр только для латиницы. Опасна была не сама ошибка, а расхождение сред:
   на PostgreSQL тот же запрос работает, и тест на SQLite перестал бы что-либо
   гарантировать. Сравнение строк подменено на знающее Юникод — только для SQLite.
3. **Мобильное меню было доделано наполовину.** `static/js/nav.js` лежал в
   репозитории с прошлого коммита, но `base.html` его не подключал, разметки с
   `#nav-toggle` не было, правил `.js-nav` в CSS тоже. Дописано и подключено.
4. **На главной преподавателя висела заглушка** «дашборд с аналитикой — на
   следующих этапах», хотя дашборд работает с этапа 11. Заменено плитками
   переходов с числом работ в очереди.

### Проверено
331 тест, 0 провалов; `check` чист; `check --deploy` в профиле `prod` — одно
предупреждение (HSTS выключен намеренно). Отдельно прогнан сценарий чистой машины:
распаковка → venv → `pip install -r requirements.txt` → `migrate` → `load_dump` →
тесты → все страницы отвечают. Появились `README.md` и `requirements.txt`.

**70 мест**, где моноширинный шрифт был приёмом оформления; остался там, где несёт
смысл — SQL, схема таблиц, вывод запроса.

### Оформление

`terminal.css` заменён на `app.css` — систему стилей, написанную заново под
существующую разметку (318 классов), чтобы не переписывать два десятка шаблонов.
Светлый лист, синий акцент, карточки с мягкой тенью, воздух. Обложки курсов
перекрашены: прежние восемь почти чёрных градиентов подбирались под тёмный фон и
на светлом читались как грязные пятна.

Прежний вид был оформлением инструмента для разработчика — чёрный фон, лайм,
консольный шрифт в навигации. Платформой пользуются студенты и преподаватели,
которым важнее спокойный длинный текст.

### Темы

Состояний три, а не два: пока переключатель не нажимали, темы следует системной
настройке; нажатие фиксирует выбор в `localStorage`, и система перестаёт
учитываться. Тема применяется **до первой отрисовки** — встроенным скриптом в
`<head>`. Это единственный inline-скрипт в проекте: внешний файл грузится
асинхронно, и между отрисовкой светлой страницы и включением тёмной темы человек
успевает увидеть вспышку белого.

### Две ошибки по пути

1. **Скрипты гасили друг друга.** `nav.js` и `theme.js` объявляли `toggle` в общей
   глобальной области — обычные `<script>` её делят. Второй файл падал целиком с
   «Identifier has already been declared», и переключатель темы не работал вовсе.
   Все три скрипта обёрнуты в самовызывающиеся функции.
2. **Тренажёр разъехался.** В разметке схема таблиц, поле запроса и вывод идут
   одним потоком, а сетка из двух колонок ставила схему слева от редактора.

### Проверено
349 тестов. Новые шесть проверяют систему стилей: каждый использованный токен
объявлен (ровно так тихо отвалился `--secondary` при смене палитры), тёмная тема
переопределяет **все** цвета, а не часть, и значения системной тёмной темы
совпадают с выбранной кнопкой — это два разных блока правил, и разойтись они
могут незаметно.

Автоматический прогон по 14 страницам × 5 ширин (320–1400) × 2 темы: 140 проверок,
горизонтальной прокрутки нет. `check` чист, `ruff` без замечаний.

## Доп. — шрифты ✅ (06.09.2026)

Собрана страница сравнения: один и тот же экран платформы, набранный семью
вариантами (скачивались Inter, Golos Text, Onest, IBM Plex Sans, Literata,
PT Serif). Выбрана пара **Inter + PT Serif**.

Inter — интерфейс и текст: крупный очковый размер, читается мелким кеглем в
таблицах отчётов. PT Serif — заголовки: антиква отделяет теорию урока от
интерфейса и уместна в вузовском контексте. IBM Plex Mono остался на SQL и коде.
Geist, Manrope и Space Grotesk удалены (последний вообще не использовался — он
без кириллицы).

Под антикву переставлена типографика: убран отрицательный трекинг (приём для
гротесков — у антиквы он съедает засечки), увеличено межстрочное расстояние
заголовков, начертания приведены к 400 и 700 — промежуточных у PT Serif нет, и
браузер подделывал бы их алгоритмически. Цифры в сводках, уровнях и результатах
тестов оставлены гротеском с табличными знаками: рядом стоящие числа должны
сравниваться взглядом. Логотип тоже гротеск — короткое слово антиквой рядом со
значком читается как заголовок статьи, а не как марка.

Проверено: 349 тестов, 70 проверок раскладки (14 страниц × 5 ширин) — смена
шрифта меняет метрики текста, поэтому прогон повторён целиком.

## Доп. — выпадающие списки и подвал ✅ (06.09.2026)

Раскрытый список нативного `<select>` рисует операционная система, и CSS до него
не достаёт — меню оставалось системным посреди оформленной страницы. Обойти это
можно двумя способами: написать свой компонент на JS, взяв на себя всё, что
`<select>` делает бесплатно (обход стрелками, Home/End, поиск по первым буквам,
объявление скринридером, родной барабан выбора на телефоне), либо включить
`appearance: base-select` — браузер отдаёт разметку меню под стили, оставляя себе
поведение. Выбран второй путь; где он не поддерживается, список остаётся
системным — ухудшение постепенное, а не поломка.

Стрелка рисуется маской, а не картинкой: маска использует только альфа-канал,
поэтому цвет берётся из токена и следует за темой. Иначе пришлось бы держать по
картинке на каждую тему.

Подвал прижат к низу окна на коротких страницах — лендинге, «сертификат пока
недоступен», «учётная запись удалена». Раньше он всплывал сразу под текстом, а
ниже оставалась полоса пустого фона. Сделано колонкой на всю высоту, а не
`position: fixed`: прибитый подвал перекрывал бы содержимое длинных страниц.
Высота считается в `dvh` — на телефоне адресная строка съедает часть `vh`, и
подвал уезжает под сгиб.

Тест системы стилей по пути поймал собственную неточность: `--chevron` — форма, а
не цвет, и требовать её переопределения в тёмной теме не нужно. Список
нецветовых токенов теперь ведётся явно, чтобы новый вносили осознанно.
