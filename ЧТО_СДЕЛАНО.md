# DataEdu (Django) — журнал миграции

Перенос DataEdu с Next.js на Django (монолит + HTMX, тренажёр на PGlite).
Next-версия не трогается — это защищаемый артефакт 1-го года. Идём по этапам.

## Этап 1 — каркас Django ✅ (25.06.2026)

- Новый проект **`dataedu-django`** (отдельный репозиторий, рядом с Next-версией).
- Окружение: **uv**, Python 3.13, **Django 5.2.15**, psycopg 3.3, python-dotenv
  (зависимости — в `pyproject.toml` / `uv.lock`).
- Каркас: проект `config`, приложение `core`, главная страница-заглушка.
- Настройки (`config/settings.py`): **PostgreSQL** через ORM (БД `dataedu_django`),
  шаблоны `templates/`, статика `static/`, язык `ru`, таймзона `Europe/Moscow`,
  секреты из `.env` (в git не входит; есть `.env.example`).
- **Дизайн Terminal** перенесён в шаблоны:
  - `static/css/terminal.css` — токены (#0C0F0D / #161A17 / #E6EDE8 / лайм #A3E635 /
    янтарь #F0B458) + шрифты Space Grotesk / Geist / IBM Plex Mono;
  - `templates/base.html` — шапка `~/DataEdu` + моно-навигация, подвал;
  - `templates/core/home.html` — герой + мок psql-терминала.
- БД создана, `migrate` (служебные таблицы Django) прошёл. `runserver` поднимается,
  главная отображается в дизайне Terminal.

### Заметки по окружению (Windows) — важно для следующих этапов
- В системе включён **SOCKS-прокси** (Internet Settings) → uv/pip падают с «tunnel
  error». Обход: ставить пакеты с `NO_PROXY='*'` (напр. `NO_PROXY='*' uv add ...`).
- Postgres: подключаться по **`127.0.0.1`** (IPv4); `::1` (IPv6) блокируется
  фаерволом (ошибка 10013). Учётные данные БД — те же, что у Next-версии (лежат в
  `.env`, в git не входят).
- Запуск сервера: `NO_PROXY='*' uv run python manage.py runserver`.

## Этап 4 — Django-admin под авторство курсов ✅ (26.06.2026)

- Админки моделей: `Course` (+ инлайн модулей), `Module` (+ уроки), `Lesson`
  (+ тесты), `Test` (+ вопросы), `Question` (+ варианты), `Assignment`. Темы —
  только суперпользователю. Пользователи/роли в админку не вынесены.
- **Изоляция авторства** (`OwnedAdmin`): не-суперпользователь видит и правит только
  свои курсы и контент под ними (через путь к `course.author`); чужое не открыть.

- Команда **`setup_teacher_admin`**: группа «Преподаватели» (28 прав на 7 моделей),
  преподаватели → `is_staff` + группа. Админ — суперпользователь, видит всё.
- Брендинг админки: «DataEdu — администрирование».
- Проверено (с откатом): второй преподаватель без курсов видит 0; после передачи
  одного курса видит 1, первый — 7; чужой курс править не может. Петрова заходит в
  `/admin/courses/course/` (200), к пользователям доступа нет (404).

## Этап 5 — витрина: каталог → курс → урок ✅ (30.06.2026)

- Приложение **courses**: представления `catalog`, `course_detail`, `lesson_detail`,
  `enroll`, `submit_review`, `complete_lesson` + маршруты.
- **Каталог** (`/catalog/`): карточки курсов с генерируемой обложкой (градиент+иконка
  по slug), бейдж уровня, рейтинг (звёзды), число уроков; **поиск** по названию,
  **фильтр** по уровню/теме, **сортировка** (популярность/рейтинг/новые); у записанного
  студента — бейдж «✓ Вы записаны» и прогресс-бар.
- **Страница курса** (`/catalog/<slug>/`): шапка, модули с уроками и галочками
  выполнения по неделям, боковая «# литература» (порт `resources.py`), **запись на
  курс**, «Продолжить →» к следующему уроку, **рейтинг и отзывы** (форма + список).
- **Страница урока** (`/lessons/<id>/`): теория из Markdown (пакет `markdown`,
  рендер в `.prose`), навигация назад/вперёд, **«Отметить пройденным»**. Места под
  тест (6), рефлексию (10), gating (9) оставлены.
- **Ролевая главная**: гость — лендинг; студент — карточка «продолжить» + каталог;
  преподаватель — ссылки на админку/каталог. Ссылка «Каталог» в навигации активна.
- Стили витрины добавлены в `terminal.css` (+ базовый адаптив боковых панелей).
- Проверено (вход студентом Дмитрием): каталог, курс, урок — скриншоты сняты,
  `check` чист. Тренажёр «Тренажёр» в навигации пока заглушка (этап 7).
